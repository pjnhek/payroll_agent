Write every test in `frontend/src/components/MutationForm.test.tsx` first, run them red, then
implement.

`MutationForm` is the only sanctioned emitter of a JSX form element alongside `ConfirmForm`. It takes
an action path and a method and renders a native form with its children, and nothing else. It must
not attach a submit handler, must not call any network API, and must not preventDefault — a plain
native POST producing a full navigation is the whole point. That native navigation is what carries the
redirect-encoded operator feedback the server sets on the redirect target, and what keeps the page
usable with JavaScript disabled.

`ConfirmForm` composes `MutationForm` and adds a submit handler that asks the operator to confirm and,
on a decline, calls the submit event's prevent-default method. Write the test for the decline path by
asserting on the event's default-prevented state, never by asserting the handler's return value:
returning a falsy value from a React submit handler does NOT cancel submission, and a test written
against the return value would pass while a Reject button became a one-click irreversible action.

Prove the semantics by mutation. Remove the prevent-default call from `ConfirmForm`, run the suite,
capture the RED case, restore it, and confirm `git diff --stat frontend/src/components/ConfirmForm.tsx`
is empty. Then replace the prevent-default call with a bare falsy return, run the suite again, and
confirm at least one test still reds — that second mutation is the one that proves the test is
asserting the right thing rather than merely asserting that some code exists. Capture both
transcripts. Before each mutation, confirm with `grep -n` that the line changed is live source and
not a comment describing the behaviour.

Prove the lint ban fires. Add a scratch component under the frontend source tree that emits a JSX
form element, run the lint script, capture the error with its rule id and the message naming the two
sanctioned components, then delete the scratch file and confirm `git status --porcelain frontend/src`
is empty.

Do NOT mount either component on the runs list page. The demo send-test form stays server-rendered
Jinja (D-22-12), which is exactly what makes the JavaScript-disabled path work; replacing it with a
React-rendered form would regress SHELL-03 in the phase that claims to preserve it. These components
exist now so Phase 23 is composition rather than invention, and their only consumer in this phase is

Pull forward the banner's SHAPE, not Phase 23's branch content.

Read the live detail template's banner region and count the branches for yourself. The structure is
a set of mutually exclusive conditional arms, an implicit fallthrough that renders no banner, and a
separate hours-changed notice that is orthogonal to all of them. Modelling this as a flat switch
silently drops the overlay, which is precisely the modelling error DETAIL-01 was written to prevent —
so the overlay must be a distinct field on the state object, never another union member.

Write `frontend/src/types/banner.ts` declaring the discriminated union with one variant per branch and
an explicit no-banner variant, plus the overlay type. Give every variant a literal discriminator field
so the compiler can narrow. Name variants after what the branch means to the operator, taken from the
template's own wording, not after the template's conditional expression.

overlay when present. Close the union with an exhaustiveness check in the default arm — assign the
narrowed value to a never-typed local — so a variant added without an arm is a compile error rather
than a silently missing banner.

Phase 22 renders placeholder-free but minimal content per arm: the banner's existing callout class
and its existing heading text from the template. Phase 23 fills in each arm's full body. This is a
functionality gap the shape makes safe to fill; it is not an architectural gap, because adding body

composition.
